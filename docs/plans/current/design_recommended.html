11 · the metric curve

decision 3
Recommended: 1.5px strokes, round joins, no smoothing by default, a single shared y-domain across overlaid runs with “free scale” as an explicit opt-out. Independent y-scales make a worse run look like a better one — which is the failure the whole Experiments module exists to prevent — and a smoothing slider would undo at the chart what the query layer's stride deliberately preserves.

05 · three named measures instead of one 760px

change
Before: ui-spec.md:115 states “desktop max-width matches the rest of the app (~760px)” as a consistency rule. 760px is a reading measure — about 75 characters at 15px — which is right for a log body and wrong for a five-column runs table. The dashboard is the worst case: a 12-column grid inside 760px is 63px per column.
Token Width Screens that declare it
--measure-prose 760px logbook, report, notes, markdown surfaces
--measure-data 1120px compare table, papers, experiments, git
--measure-wide min(100vw − 2rem, 1600px) graph (focus mode), dashboard
The dashboard keeps 12 columns above 1200px and drops to 6 at prose width. Three tokens, and every screen states which one it takes.
What is not on this page: the eight claims in the audit that describe an older app — Settings-as-a-scroll, “red 14px delete”, graph focus mode on a branch, eleven themes, no contrast gate, no card or empty-state primitive, three tree UIs, no reduced-motion story. Each was checked against the file it names; the ledger is design_audit_verification.md, and the side-by-side is design_changes.html.
