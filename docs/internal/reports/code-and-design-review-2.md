## 2. Verdict

The architectural claims in the project's own documentation are, unusually,
true: the layering holds in the main flow, the boundary gates run on every PR,
and the domain core is genuinely framework-free and heavily tested. The RLS
sweeps are careful and the previous review's fixes all hold.

The problems cluster in two places:

1. **Trust seams.** Where a token, a path, or a client-supplied row crosses from
   one subsystem to another, the check is missing or weaker than the surrounding
   prose claims. The MCP relay token that also authenticates SDK routes, the
   metric ingest that never checks which experiment it writes to, the blob
   registry that never binds a path to its owner, and the desktop preload bridge
   that attaches to whatever origin it is pointed at are all the same shape.
2. **The Android track is not in the repository.** The entire Android source
   tree is gitignored and regenerated by an unpinned CLI at release time, while
   CI asserts it builds "from the committed Bubblewrap project".

Everything below is ordered by severity within its area.

### A1 — an anonymous client can take DDL locks

```sql
create or replace function sync_prepare() returns void
language plpgsql
security definer
set search_path = public
as $$
  ...
  execute format('alter table public.%I add column if not exists server_seq bigint', t);
  execute format('create index if not exists %I on public.%I (server_seq)', t || '_server_seq_idx', t);
```

Postgres grants `EXECUTE` to `PUBLIC` by default, and no `revoke` for this
function exists in any migration. The grant-hardening migrations `0079` and
`0081` work from hand-maintained lists written before `0118` existed — which is
exactly how this slipped through. Any client can call it repeatedly and force
`ACCESS EXCLUSIVE` locks plus a full-table `update` on every registered table.

**Fix:** `revoke all on function sync_prepare() from public;` and replace the
enumerated revoke lists with a generated check (see G-tooling).

### A3 — curve poisoning through a shared experiment

The route inserts client rows verbatim:

```ts
toInsert.push(...keep);
...
const { error } = await user.db.from("experiment_metrics").insert(toInsert);
```

and the only insert-time constraint in the database is ownership of the row's
own `user_id`:

```sql
create policy "experiment_metrics_insert_own" on experiment_metric_points
  for insert with check ((select auth.uid()) = user_id);
```

SELECT, by contrast, is widened by `shared_to_me('experiment', experiment_id)`.
So a collaborator can insert points tagged with their own `user_id` that point at
the owner's `experiment_id`, and the owner's charts render them as their own
results. Overwriting an existing step is blocked by the owner-only UPDATE policy;
appending new steps is not.

**Fix:** require `exists (select 1 from experiments e where e.id = experiment_id
and e.user_id = auth.uid())` in the insert policy, or check ownership in the
route before insert.

### B1 — the scope the relay token was supposed to have

`0072`'s own header states the intent plainly:

```sql
-- Relay-only tokens cannot authenticate SDK routes. Existing tokens retain
-- their SDK scope; MCP tokens receive a separate, revocable scope.
```

and the relay resolver honours it with `and 'mcp_relay' = any(scopes)`. But the
SDK resolver, which `requireSdkUser` calls for any token in API-token format,
filters only on expiry:

```sql
select id, user_id into v_id, v_user_id
from api_tokens
where token_hash = p_token_hash
  and (expires_at is null or expires_at > now())
limit 1;
```

MCP tokens are minted with `expires_at: null` and handed to a third-party MCP
client. That same token therefore resolves as an SDK token and unlocks
`GET /api/settings/credentials` (which returns the user's decrypted Zotero and
Semantic Scholar keys), `/api/sdk/artifacts`, and `/api/sdk/experiments`.

**Fix:** add `and 'sdk' = any(scopes)` to `resolve_api_token`, or enforce the
scope in `requireSdkUser`.

### B2 — unbounded upload

```ts
form = await request.formData();
...
await store.upload(bucket, path, file, ...);
```

The artifact route next door refuses on content-length before calling `json()`
and estimates base64 size before decoding. This route has neither a
content-length check nor a byte cap, and `formData()` buffers the request before
`arrayBuffer()` copies it again. Any token holder can exhaust memory or fill
storage in one request. This is materially worse while B1 stands.

### 5.1 Pitch site — reviewed, sound

### D1 — the updater's own comment says this

```ts
 * SECURITY: the Windows build is not code-signed, so the only integrity check
 * on a downloaded update is the SHA-512 in `latest.yml`, which is fetched over
 * HTTPS from the same GitHub release. That is a real check, and it is weaker
 * than a signature...
```

paired with:

```ts
updater.autoDownload = true;
updater.autoInstallOnAppQuit = true;
```

The weakness is documented rather than hidden, which is to the author's credit —
but the consequence is that silent code execution is one TLS or GitHub-account
compromise away, on every installed machine, with no user prompt at the point of
install. Either sign the build, or set `autoDownload = false`, or make the
install explicit rather than automatic on quit. Two update paths also coexist:
this silent one and the notify-only path in `apps/desktop/src/update-check.ts`,
which is what that file describes as the deliberate contract.

### D2 — the trust boundary rests on one function

`preload.ts` ends with an unconditional `contextBridge.exposeInMainWorld`, and a
scan of all 25 `ipcMain.handle`/`ipcMain.on` registrations shows every one takes
`_event`, discarding the sender. Nothing checks who called.

The compensating control is real and deliberate — the navigation guard is
documented as existing for exactly this reason:

```ts
 * Without them a page can navigate the shell itself to an arbitrary site, and
 * that site would then be a page with a preload attached.
```

So for a normally built, bundled app the window only ever loads `app://`, and the
bridge is effectively confined. The finding is therefore about defence in depth
rather than an open door: the entire isolation of a surface that includes
`dbQuery` (raw SQL), vault read/write, secret writes and `localApiSet` depends
on `APP_URL` never being a foreign origin. Two configurations break that
assumption — `WEAVEFORGE_URL` (the documented dev override) and a shell built
with a `__DEFAULT_APP_URL__` that is not the operator's own deployment, which is
also what happens if that default is ever plain HTTP.

**Fix:** validate `event.senderFrame.url`'s origin in one shared wrapper around
IPC registration. That is the same refactor as **D11** — extracting
`registerChannels(deps)` out of `main.ts` — so the two are worth doing together.

### D5 — a feature that cannot work

`argFor` passes `--print`, so tectonic writes the PDF to stdout; the code then
reads `path.join(root, entry.replace(/\.tex$/i, "") + ".pdf")`, which tectonic
never created. `ok` is therefore always false on a tectonic-only machine, and
the promisified `execFile` UTF-8-decodes binary stdout into the log. On machines
that also have `latexmk` this is invisible, because `latexmk` is probed first —
which is presumably how it survived.

### D11 — no CI coverage for the desktop

`grep` across `.github/workflows` for `test:desktop` returns nothing. The
`check:all` script includes `npm run test:desktop`, but `check:all` is not what
CI runs. Running the suite by hand in this pass gives **147 passing tests across
6 suites in ~14 s** — the tests are real, fast and maintained; they simply never
execute on a pull request. The largest desktop module, `main.ts` at 745 lines,
is also the one with no test file, and it holds the ordering and race findings
above.

### E1 — "committed" is not true

```
$ git ls-files apps/web/twa
apps/web/twa/README.md
apps/web/twa/twa-manifest.json
```

Everything else — `AndroidManifest.xml`, the three Java classes, every
resource, `build.gradle`, the gradle wrapper — exists only on this machine. The
`.gitignore` entry meant to protect generated output ignores `apps/web/twa/app/`
rather than the Gradle `build/` output directory beneath it. Bubblewrap's `update` deletes `app/` and
`build.gradle` before regenerating, so any hand edit is destroyed on the next
release. The correct ignore is the build directory, not the source tree.

Note the keystore and APKs are correctly ignored and no secret leaked — that
part of `.gitignore` is right.

### E2 — the gate that checks half the link

```bash
if ! grep -q "$FP" "$ASSETLINKS"; then
```

The fingerprint half of Digital Asset Links is verified. The `package_name`
half is not, and neither is the host — a mismatch in either leaves the TWA
unverified with the URL bar showing, which is the exact failure this step exists
to prevent. Given E3, where two sources of truth for the app identity already
disagree, this gate is the only thing that could have caught the drift and does
not.

### F1 — the docstring describes the bug it does not prevent

`normalize_wall_time` exists precisely for this:

> Sources disagree on format: wandb's `_timestamp` is epoch **seconds**
> (float) ... Without this, an epoch float reaches Postgres as `"1699999999.0"`
> and the insert fails. `None` stays `None`; strings are assumed already
> parseable.

The comment two lines into the range check then reads:

```python
return str(value)          # metric_point.py:32 — "already parseable"
...
series.add(int(step), float(value), str(wall) if wall is not None else None)   # wandb.py:37
```

The `isinstance(value, (int, float))` branch that would have converted the epoch
correctly is never reached, because `wandb.py` stringifies the float before it
is passed. The payload key matches the column (`"wall_time"`), so the string
travels straight into `timestamptz`. The test asserts only step and value, which
is why this is invisible.

### F2 — the pruner crashes on its own target case

```ts
const maxStep = Math.max(...storedSteps);
```

A spread of ~125 000 arguments overflows the V8 call stack. The pruning script
selects every step of an over-budget series, so the series large enough to need
pruning is the one that crashes the pruner. The existing retention test uses a
seven-element array.

### G1 — fail-open gates

```js
function rg(pattern, extraArgs = "") {
  try {
    const out = execSync(`rg -l "${pattern}" apps/web/src/features ${extraArgs}`, {...});
    return out.trim().split(/\r?\n/).filter(Boolean);
  } catch (e) {
    if (e.status === 1) return [];   // "no matches" — but also "rg not found"
    throw e;
  }
}
```

On POSIX a missing binary exits 127 and the gate throws, which is correct. On
Windows Node spawns through `cmd.exe`, which reports "command not found" as
exit 1 — indistinguishable from "no matches". Two further rules swallow every
error with a bare `catch { return []; }`. The repository depends on ripgrep
being installed and never checks.

This matters more than a normal tooling nit because the boundary gates are
presented in `CONTRIBUTING.md` and `docs/building/dev.md` as the mechanism that
prevents architectural decay. On a Windows contributor's machine they can be
entirely inert. (During this review the gates crashed with `EPERM` rather than
passing, because the sandbox blocks the spawn — so the fail-open path is argued
from the exit-code semantics, not from a rejection observed here.)

## 10. Prioritised remediation plan

### Phase 1 — trust seams (do first; each is small and independent)

1. Add `and 'sdk' = any(scopes)` to `resolve_api_token` (**B1**) — one line; it
   closes credential disclosure to a token handed to third-party software.
2. `revoke all on function sync_prepare() from public` (**A1**).
3. Bind the metric insert to experiment ownership (**A3**).
4. Refuse oversized uploads before buffering, as the artifact route already
   does (**B2**).
5. Fix the W&B wall-clock stringification (**F1**) and the `Math.max` spread
   (**F2**) — the first makes the feature work, the second stops the pruner
   crashing.
6. Stop auto-installing unsigned updates, or sign them (**D1**).
7. Commit the Android source tree and narrow `.gitignore` to the build output
   (**E1**); compare `package_name` as well as the fingerprint (**E2**).

### Phase 2 — correctness and resilience

8. Harden the desktop renderer trust boundary: verify the sender origin before
   exposing or acting on bridge calls (**D2**), remove the `null` CORS header
   (**D3**), and bound the loopback upload read (**D8**).
9. Fix the tectonic argument vector (**D5**) and give the PDF path a real
   result, or drop tectonic from the probe order until it works.
10. Make the desktop quit path bounded so a hung close cannot hold the
    single-instance lock (**D6**), and serialise the two stores' writes (**D7**).
11. Give the training crash path a `try/finally` so status is always recorded
    (**F3**).
12. Run the repository contract suites against the real adapters, and implement
    or remove the API adapter methods that raise `NotImplementedError`
    (**F4**).
13. Introduce an error root with typed not-found, and map it consistently to
    HTTP status (**F5**).
14. Add transactions for the org flows (**B8**) and request guards for body size
    and rate (**B2, B3, B5**).

### Phase 3 — structural and hygiene

15. Make ripgrep a checked prerequisite, and split the gates into one CI step
    each (**G1, G4**).
16. Run the desktop test suite in CI (**D11**), and extract IPC registration out
    of `main.ts` so the ordering logic becomes testable.
17. Add a `Summary` projection type instead of overloading full entities
    (**F6**).
18. Add Dependabot and SHA-pin every action (**G2, G3**).
19. Move the settings panels' HTTP calls behind facades and delete the UI →
    infrastructure imports (**C1, C2**).
20. Add per-route error boundaries that do not offer to wipe local data
    (**C4**), and fix the `MultiSelect` keyboard model (**C6**).

## 11. Coverage gaps worth naming

- **Nothing asserts RLS policy completeness.** No test checks that every command
  has a policy, that `WITH CHECK` exists, or that a `security definer` function
  is not executable by `public`. A1 and A6 are both instances of that blind
  spot, and the PGlite harness already runs the migrations and could host the
  assertion.
- **The RLS integration suite covers two areas, not the schema.** It applies
  every migration cleanly and passes (`MCP relay and proposal RLS`,
  `reader_annotations`), which proves the migrations *apply* — but nothing in it
  touches `sync_prepare` (A1), the `blob_objects` path/owner binding (A2), or
  the metric-insert ownership gap (A3). Those three are exactly the cases where
  a passing suite is mistaken for a checked one.
- **Nothing verifies that a migration does not read a table a later migration
  dropped** (A6).
- **The desktop suite does not run in CI** — 147 tests that pass and never
  gate a merge (D11).
- **The route-test gate is satisfied by an empty test.** G6: 18 of 34 route
  tests assert only "401 without a token", and nothing covers the tiered blob
  path, org authorization at the route level, upload size, or the token-scope
  seam in B1.
- **UI component coverage is near-zero.** Of 176 test files in the web app, only
  two render a component. `Modal`, `Select`, `MultiSelect`, `Popover` and
  `useScreenData` have no tests — which is exactly where C3 and C6 live.
- **No end-to-end coverage** for plan, logbook, graph, lists, wiki, the
  dashboard grid, or the pitch page.
- **The Python tests miss every failure path found here**: the W&B wall-clock
  value is never asserted (F1), and the crash-path flush is never combined with
  a failing flush (F3).
- **The retention test uses seven points** (F2).

## 12. Limits of this review

Stated so the findings are not over-trusted:

- No live database, device, or packaged build was exercised. RLS behaviour was
  read from the migration sequence, not from a running Postgres; the Android
  findings are from source and workflow configuration, not from an installed
  APK; the desktop findings are from source, not from a running Electron app.
- The `sync_prepare` exposure (A1) and the metric-write hole (A3) are argued
  from policy text and default grants. Both should be confirmed against a live
  database before being called exploitable in the field.
- `mypy`'s single error is environmental (see §1) and is not counted as a
  finding.
- Playwright traces uploaded by CI are configured without credential redaction
  and produced by a job holding test-account passwords; whether a trace actually
  contains them was not checked.
- `.github/branch-protection.json` exists in the repository but whether it has
  been applied to the GitHub repository cannot be determined from here.
