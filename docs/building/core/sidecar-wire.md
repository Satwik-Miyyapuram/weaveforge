# Sidecar wire rules

Rust port of the pure parts of `apps/shell/sidecar/src/wire.ts`.

- Rust: `crates/wf-core/src/wire.rs`. Tests: `crates/wf-core/tests/sidecar_wire.rs`.
- wasm: `crates/wf-wasm/src/wire.rs` exports `wireRoute`, `wireParseRequest`, `wireTag`, `wireErrorReply`, `wireOkReplyHead`.
- TS wrappers: `packages/wf-wasm/src/wire.ts`, typed entries on `RustCoreFns` in `packages/core/src/shared/rust.ts`.
- Shim: `apps/shell/sidecar/src/wire.ts` keeps readline, the handler table, ask timers, `createPeer`, `serve` and the JS-side tag conversion.

## What Rust decides

- **Routing** (`route_line`): an answer line goes to the peer when one listens, a blank line is skipped, a line over `MAX_LINE` (32 MiB, UTF-16 units) gets `bad request: line too long`, anything else is parsed as a request.
- **Requests** (`parse_request`): `id` must be a non-negative safe integer and `method` a non-empty string. Errors are `bad request: not JSON` and `bad request: needs an integer id and a method`. Arrays are refused.
- **Answers** (`parse_answer`): `answer` is an integer of at least 1, `ok` a boolean, and `error` a string when `ok` is false.
- **Tags** (`wire_tag`): a value with exactly one key, `$bigint` (a string matching `-?\d+`) or `$bytes` (a string). Anything else is not a tag.
- **Reply shapes**: `error_reply` (`{id, ok:false, error}`, id may be null) and `ok_reply_head` (`{id, ok:true}`). The shim adds `value`.

## What stays in TS

- Node sockets and `readline`, and the `MAX_LINE` guard in `settleLine` before the Rust call.
- The handler table: the unknown-method check (`Object.hasOwn`) needs the handlers, so the shim builds that error through `wireErrorReply`.
- Ask and event frames, the ask timers and `MAX_ASKS`.
- The tag conversion. Rust cannot hold a JS `bigint` or `Uint8Array`, so Rust recognises the tag and TS builds the value. Base64 stays in JS.

## Known limits

- `parseRequest` and the answer path keep tags as plain objects from Rust, and `reviveTags` walks them. The walk calls Rust only for one-key objects, so a deeply nested tree costs one serialisation per one-key object on its path.
- An absent answer `value` is `null` on the Rust side and `undefined` in the original JS. The shell sees `null`.
- Ids written as floats (`1.0`) are refused in Rust. The TS version accepted them.
- `wf-bindings` and `bindings.ts` are not regenerated by this change.

## Tests

`crates/wf-core/tests/sidecar_wire.rs` ports the non-ask cases of `apps/shell/sidecar/test/wire.test.ts`. The TS test file still needs wasm preloaded (`test/preload-rust.ts`), or the coordinator retires it.
