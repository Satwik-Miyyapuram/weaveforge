# Proposal inputs core module

The `proposal_inputs` module holds the input types for AI write proposals. The types
carry `specta::Type` derives, so they generate into `bindings.ts`. The validators are
in `proposal_payload`.

## What lives in Rust

The input types are `ExperimentFollowUpInput`, `PaperAnnotationInput`,
`PaperFieldDefInput`, `PaperFieldFillInput`, `PaperUpdateInput`,
`ReadingListChangeInput`, `RelationInput`, `VaultNoteEditInput` and `VaultNoteInput`.
Each derives `Deserialize` with `camelCase` names and `#[serde(default)]` where a
field is optional.

Three inputs are registered under other names: `ProposalLogEntryInput`,
`ProposalZoteroPaperInput` and `ProposalMilestoneInput`. Their serde renames match
the TypeScript shapes.

`ExperimentUpdateInput` has no specta derive. It is the only one not in
`bindings.ts`.

Source: `crates/wf-core/src/ai/proposal_inputs.rs`. Registration is in
`crates/wf-bindings/src/lib.rs`.

## What stays in TypeScript, and why

- **Callers' own types.** The wrappers use the generated `bindings.ts` types. They do
  not declare their own.
- **Regeneration.** `bindings.ts` is regenerated by the coordinator. It is not edited
  by hand.
