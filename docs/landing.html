The decorator does everything

Two lines in your training loop.

It creates the run, pins it to your current git commit, records metrics and figures, marks it done or failed, and pulls your TensorBoard / wandb curves on exit.

# pip install thesis-tracker
from thesis_tracker import track_experiment

@track_experiment(name="β-VAE sweep", config={"latent_dim": 32},
                  related_paper="higgins-2017",          # ← ties the run to your literature
                  sync={"tensorboard": "runs/beta4"})   # ← pulled into the dashboard on exit
def train(run, beta=4.0):
    for step in range(100):
        run.log_metric("val_loss", loss(step), step=step)   # → curve
    run.log_figure(fig, name="reconstruction")             # → dashboard
    return {"val_loss": 0.118}                          # → summary metric

Using a framework? Skip instrumenting the loop — drop in a callback: ThesisTrackerCallback for PyTorch Lightning and Keras.

Sync

Bring your existing logs

Import scalar curves from TensorBoard event files or a wandb run, and attach matplotlib figures — through one sync call or a decorator.

Extensible

Add your own source

A source is a small class you register — no fork, no SDK edits. TensorBoard, wandb, and matplotlib ship built in; your CSV logger is three methods away.

Thesis-native

Experiments meet literature

Tie a run to the paper it tests and see it on the card. Your sweeps, your reading list, and your report outline live in one workspace.

Typed SDK

Clean, SOLID, tested

A framework-agnostic core with repository contracts, a typed (py.typed) Python SDK, and contract tests shared across every backend.

Live

Watch a run stream

Metrics and status update on their own while a run is in progress — no refresh, no polling loop to babysit.

Yours

Own your data

Everything writes to your Supabase project behind row-level security. The anon key is public by design; your runs never touch anyone else's servers.

Get started

Running in a few minutes.

Point the SDK at a free Supabase project, apply the migrations, and track your next run.

# 1 · install the SDK (with the sync sources you use)
pip install thesis-tracker
pip install 'thesis-tracker[tensorboard,wandb,figures]'

# 2 · point it at your Supabase project
export THESIS_TRACKER_SUPABASE_URL=https://<ref>.supabase.co
export THESIS_TRACKER_SUPABASE_ANON_KEY=eyJ...
export THESIS_TRACKER_EMAIL=you@example.com
export THESIS_TRACKER_PASSWORD=········
export THESIS_TRACKER_PROJECT="My Thesis"

# 3 · track a run from the CLI or the decorator
thesis-tracker import-tb runs/beta4 --name "β-VAE sweep"
